What you are viewing

Each specimen comes from the original vector outlines in the official consolidated Unicode code charts. This is a snapshot of the repertoire in a particular release, including characters introduced in earlier releases. It is not a history of every previous glyph revision.

Regional CJK and other source forms are retained individually with their printed identifiers. Combining marks keep the chart’s dotted-circle helper. Noncharacters retain the PDF’s black cell and white label where present; those cells are conventions, not assigned characters.

Release and draft status

The monthly workflow discovers the final release from Unicode’s official latest-version ReadMe and checks the public draft directory. New codepoints assigned only in the draft are shown in red and explicitly labeled “Draft”. Draft forms for already released characters can be inspected separately. Drafts are work in progress and may change or disappear.

Exact vectors, compact storage

The published files use SVGZ: gzip compression of the complete original SVG, including its paths, metadata and source notices. Compression is checked by an exact byte-for-byte round trip. The website decompresses specimens in your browser. The extractor produces ordinary SVG files as well.

Every exported file is checked against the source inventory. A separate audit compares every PDF outline and its position with the SVG collection. Reports, input hashes and compressed manifests are available in the collection repository. Extraction and audit scripts are in unicode-glyph-extractor.

Illustrative shapes

Reference glyphs are not prescriptive designs. Actual fonts may vary. The charts do not contain every emoji sequence, shaping combination, or ideographic variation sequence. Unassigned codepoints, private-use ranges and surrogate ranges have no individual reference glyphs in this collection.
